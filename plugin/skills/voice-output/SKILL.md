# Voice Output — обязательная озвучка ответа

## Главное правило (НЕ ОПЦИОНАЛЬНО)

**Озвучка идёт ПЕРВОЙ, до основного текста ответа.** Порядок в каждом ответе:

1. Сформулируй финальный ответ пользователю в голове целиком.
2. **Первым tool-вызовом** в ответе зови `mcp__claude-tts__speak` с этим текстом, очищенным от markdown/кода/путей. Звук пойдёт пока я пишу.
3. Затем пиши тот же самый текст в чат (с markdown, кодом, путями — как обычно для глаза).

**КРИТИЧНО: текст, который ты передал в `speak`, и текст, который ты пишешь пользователю в чат, должны быть содержательно одним и тем же ответом.** Не сочиняй для голоса один вариант, а для глаз другой. Разница только в форматировании — markdown/код/пути убираются для голоса, остальное идентично.

Без исключений на основании "техническая отладка", "много кода", "ответ короткий", "пользователь не просил голос явно" — таких исключений НЕТ.

Единственные легальные основания пропустить `speak`:
1. Пользователь в этом конкретном сообщении сказал "молча", "без звука", "не озвучивай", "тише" в смысле выключи озвучку этого ответа.
2. Очищенный текст после удаления кода/путей/markdown оказался пустым (нечего читать).
3. Предыдущий вызов `speak` в этой же сессии вернул ошибку — пропусти ОДИН раз, потом снова пробуй.

Во всех остальных случаях — `speak` обязателен.

## Что озвучивать

Готовь текст для `speak` так, чтобы он звучал нормально на слух:

1. **Убрать Markdown-разметку**: звёздочки `*`, решётки `#`, бэктики, скобки `[text](url)` → оставь `text`.
2. **Удалить блоки кода целиком** (между ``` или ~~~). Код вслух бесполезен.
3. **Удалить пути файлов** (`C:\...`, `/sessions/...`), `computer://` ссылки, длинные ID и хеши.
4. **Таблицы** заменить на короткое словесное резюме ("три строки: А делает X, Б делает Y, В делает Z").
5. **Списки пунктов** — озвучить как нумерованный перечень голосом ("первое... второе...").
6. Оставить обычные предложения, осмысленные выводы, рекомендации, ответы на вопросы.

## Длина

- Короткий ответ (`Да`, `Нет`, `Готово`) → озвучить как есть.
- Средний (1–5 абзацев) → озвучить полностью после очистки.
- Длинный (>3000 символов после очистки) → озвучить краткое резюме первых 1–3 предложений плюс финальную мысль. Не читай простыню целиком.

## Команды управления голосом

Если пользователь дал команду на голос — выполни сначала её, потом обычное правило `speak`:

| Пользователь сказал | Tool |
|---|---|
| "переключи на Свету" / "Светлану" | `set_voice` name=Svetlana |
| "переключи на Дмитрия" | `set_voice` name=Dmitry |
| "переключи на Ирину" | `set_voice` name=Irina |
| "быстрее" | `set_rate` +1 (узнать текущее через `get_state`) |
| "медленнее" | `set_rate` -1 |
| "громче" / "тише" | `set_volume` ±10 |
| "покажи голоса" | `list_voices` |
| "стоп" / "хватит читать" / "замолчи" | `stop` (и НЕ зови `speak` для этого ответа) |
| "пауза" | `pause` |
| "продолжай" | `resume` |

## Технические правила

- `speak` асинхронный — вызывай как **первое** tool-действие в ответе (если в этом ответе нужны и другие tool-вызовы, ставь speak самым первым). Не жди завершения речи.
- Если `speak` вернул ошибку — не извиняйся пользователю, не повторяй. Игнорируй для этого ответа.
- Не озвучивай служебные tool-output: bash-вывод, JSON, диагностика. Только финальный текст для человека.
- При длинных tool-цепочках финальный `speak` всё равно нужен — озвучь суть ответа.

## Самопроверка перед отправкой

Перед тем как начать писать ответ пользователю проверь: **вызвал ли я уже `mcp__claude-tts__speak` первым tool-вызовом в этом ответе?** Если нет и нет легального исключения — зови сейчас, перед текстом.

И второе: **совпадает ли содержательно то что в speak с тем что я пишу в чат?** Если нет — переделать, единый ответ для уха и для глаза.
